# FORGE HITPAY: rulings on the review (2026-11-16)

Rulings WIN over HITPAY-FORGE-SPEC.md where they differ. Numbers = HITPAY-FORGE-REVIEW.md findings.

## Blockers
- **R1 (B1) one payment row per HitPay request.** Never overwrite `intent_id` and never DELETE an old request (a buyer may be on it). A new request creates a NEW `payments` row (pending, intent_id = request id). If the order already has a pending hitpay payment created < 20 min ago with the same amount, reuse its url (no new request). Webhook / return / reconcile find the payment by `intent_id == payment_request_id` (exact, gateway hitpay) — never by order-number fallback. Any verified-completed request → that payment succeeded → order paid (via existing `markPaid`). If the order is already paid by another payment → order unchanged, this payment flagged `meta.double_payment=true`, owner email "refund in HitPay dashboard". Same rule for AV/NF: `pay_requests` child table (order_ref, request_id UNIQUE, amount_sen, status, created_at).
- **R2 (B2) return route.** New named route per existing pattern (`shop.php`), e.g. `checkout.return.hitpay` → `checkout/return/hitpay/{order:number}`, URL built by `ReturnUrls` (signed). Add `reference` and `status` to `gatewayQueryKeys()`. Handler must also cope if HitPay appends with `?` instead of `&` (unverified): parse leniently; if the signature still fails but the session owns the order, proceed; otherwise show the standard "order received, we'll confirm by email" page — never 404 a payer.
- **R3 (B3) AV/NF secrets** = encrypted fields in the CMS settings table (encrypted with the existing `secret.key`), editable only by the admin role in a new panel section "Payments (HitPay)": api key, salt (write-only inputs, shown masked), "Order notification email" (R15), "Delivery fee (RM)" (§5.1 — moves here from the json file), "Test connection". No secrets file, no FTP above docroot. The integrator sets the values through the authenticated panel API after deploy.

## Majors
- R4 HitPay keys/enabled live under `commerce.gateways.hitpay.*` / whatever `PaymentManager::isReady` actually reads (follow Stripe's exact plumbing incl. test/live mode split; HitPay uses live mode only, sandbox fields allowed but optional).
- R5 No new status enum values. Amount/currency/reference mismatch on a completed request → payment `meta.needs_review=true`, order stays pending, timeline note + owner email; reconcile skips it. Exact-amount check (integer sen) happens in the HitPay verify step BEFORE `markPaid`.
- R6 `HitpayGateway::settleRequest(string $requestId)` = fetch-verify then `markPaid` / `markFailed`. Webhook handler, return page, thank-you page and reconcile all call it. Webhook body never sets state.
- R7 Fetch says still `pending` during a webhook → throw → existing ingest deletes the dedupe row and answers 500 → HitPay retries.
- R8 Hold is 30 min on both stores → `expires_after = "25 mins"`. Request-level `failed` = keep pending until expiry (buyer may retry on the same page); `expired|canceled` → markFailed + release stock.
- R9 Thank-you page re-check and the retry link become gateway-generic (hitpay included).
- R10 Host verified from the live probe: `https://checkout.hit-pay.com/payment-request/@berkat-madinah/<id>/checkout`. Add a SEPARATE `form_action_hosts` list (do not widen script/connect/frame-src). Redirect host guard: exact `checkout.hit-pay.com`, https.
- R11 hmac from the RAW body: `parse_str($request->getContent(), $f)`; `$h=$f['hmac']??''; unset($f['hmac']); ksort($f); $s=''; foreach($f as $k=>$v){$s.=$k.$v;} hash_equals(hash_hmac('sha256',$s,$salt),$h)`. Unit test with a fixed vector computed by that code (document that the vector is self-generated).
- R12 Refunds stay out of scope; hide the refund action for hitpay payments in panel + return page; panel shows "Refund in the HitPay dashboard".
- R13/R14 AV paid page = own lazy route `/en/order/paid` + `/ms/order/paid`, added to App router, prerender list, reserved slugs; noindex; excluded from sitemap/llms/hreflang gates. Bundle gate must stay green — measure.
- R15 AV owner email: `notified_at` set only when `mail()` returns sent; un-notified paid orders retried on every status poll, admin list view, and create call (max 3 per call). Recipient = new setting "Order notification email" (default: the recipient configured on the existing contact form — builder finds it; record which).
- R16 Build the rate limiter: SQLite `rate_hits(bucket, ip_hash, ts)`; create 10/10 min/IP, status 60/10 min/IP; prune > 1 day on write.
- R17 AV/NF idempotency: client sends `idem` (random UUID created when the order is frozen, kept in `avo.order.v1` / NF equivalent). Same idem → same order; if it has a pending request < 20 min old with the same total → return its url; else new request row (R1). Cart changed → new idem.
- R18 AV/NF paid page reads ref+token from local storage first, query second. NT/SIH see R2.

## Minors adopted
Enum ALTER branches on driver (mysql/mariadb only; sqlite test DB skips); all money in integer sen, format `number_format($sen/100,2,'.','')`; amount ≥ 30 sen check; refunded/partially-refunded payments in a completed request → treat as not-paid + needs_review; AV order ref date in `Asia/Kuala_Lumpur`, server-generated, retry on UNIQUE collision; phone sent as `+60…` E.164 or omitted; AV has no email field → don't send email; NF paths `/noor-fes/paid/` and `/noor-fes/ms/paid/`; NF deploy must delete old `public/pay/*` QR files if any were uploaded (none: folder empty); NF price comes from the AV server table at build time of AV — NF repo keeps its display price and a test asserts it equals `server/_data/noorfes.json` read by relative path `../avoliveoil-v2` only when present (skip otherwise); never call HitPay inside an SQLite transaction; create-time sweep max 3 orders; integrator proves cron with `crontab -l` before relying on reconcile; stored webhook payloads keep only ids/status/amount (no phone); AV orders list = admin role only; panel currency for hitpay forced to MYR in code; "Test connection" gets its own hitpay branch; one HitPay request per order at a time also limits double stock holds (NT/SIH reuse R1).
